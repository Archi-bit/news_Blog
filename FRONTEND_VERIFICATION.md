# Проверка React Frontend — этап 2

Дата: 9 октября 2026, Asia/Bishkek.

## Реализовано

React 19, JavaScript, Vite, React Router, Axios и локальные шрифты с кириллицей. Все 15 требуемых страниц, адаптивная лента, темы, поиск, редактор с предпросмотром и изображениями, публикация/черновики, профили, комментарии, лайки и подписки. Состояния загрузки, пустые списки, ошибки, toast-уведомления, подтверждение удаления и мобильная навигация.

JWT хранится в памяти. Refresh использует HttpOnly cookie с CSRF-защитой. Сессия восстанавливается при перезагрузке; параллельные запросы после HTTP 401 объединяют обновление токена. Публичные медиа доступны через Vite proxy. Сохранение изображений и пустого списка тегов происходит одним реальным multipart PUT.

Единственное функциональное дополнение API: read-only `is_staff` в собственном профиле, чтобы показать администратору разрешённые действия. Публичные профили не раскрывают этот флаг; клиент не может изменить его.

## Браузерные сценарии

1. Гость: настоящая лента API, пагинация, сортировка, категории, поиск, пустые результаты и 404.
2. Автор: регистрация и проверка паролей, вход, HttpOnly cookie и отсутствие токенов в localStorage/sessionStorage; два настоящих HTTP 401 и один refresh; обложка, предпросмотр, черновик и его недоступность гостю; публикация, лайк/отмена; создание/редактирование/удаление комментария; редактирование статьи с удалением всех тегов и повторной загрузкой обложки; снятие с публикации и повторная публикация; восстановление сессии после reload; аватар и профиль; подписка/отписка; удаление статьи, logout и защита маршрутов.
3. Неверные учётные данные: реальная серверная ошибка отображается в форме.
4. Мобильный экран: меню, поиск, регистрация, отсутствие горизонтальной прокрутки и Axe.
5. Сбой сети: сообщение об ошибке и успешная повторная загрузка после восстановления соединения.

Успешные API-ответы в тестах не подменяются. Для тестов ошибок прерывается сеть или изменяется исходящий Authorization; ответы Django и последующее обновление сессии остаются реальными. Пользовательское содержимое с `<script>` отображается текстом и не исполняется.

## Воспроизведение

```bash
docker compose up -d --build --wait
docker compose exec frontend npm run lint
docker compose exec frontend npm run format:check
docker compose exec frontend npm run build
docker compose exec backend pytest -q
# Браузерные тесты на хосте: Node.js 22.13+ и Google Chrome.
cd frontend
npm ci
CHROME_PATH=/usr/bin/google-chrome npm run test:e2e
# Затем из корня проекта:
python3 scripts/cleanup_e2e.py
```
